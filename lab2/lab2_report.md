# Лабораторная работа №2. Исследование Cloud Run

## Цель работы

Ознакомиться с возможностями Cloud Run, изучить процесс развёртывания приложений, мониторинг их работы и управление трафиком между версиями.

## Ход работы

### 1. Создание сервиса Cloud Run

В Google Cloud Console был создан сервис `hello` на основе стандартного тестового контейнера:

`us-docker.pkg.dev/cloudrun/container/hello`

Для сервиса установлены следующие параметры:

| Параметр | Значение |
|---|---|
| Регион | europe-west1 (Belgium) |
| Порт контейнера | 8080 |
| CPU | 1 vCPU |
| Оперативная память | 512 MiB |
| Минимальное число экземпляров | 0 |
| Максимальное число экземпляров | 1 |
| Масштабирование | Автоматическое |
| Модель оплаты | Request-based |
| Доступ | Публичный |

После развёртывания была создана первая версия приложения `hello-00001-vdd`.

Сервис успешно запустился и стал доступен по публичному URL.

### 2. Анализ логов и метрик

В разделе `Observability → Logs` были изучены события запуска контейнера и обработки HTTP-запросов.

В логах зафиксированы:
- Успешное создание сервиса и запуск контейнера.
- Успешная проверка доступности порта 8080.
- HTTP-запросы GET со статусом 200.
- Время обработки отдельных запросов от 3 до 9 мс.

### 3. Изменение порта контейнера

В настройках Cloud Run порт контейнера был изменён с `8080` на `8090`.

После повторного развёртывания создана новая версия `hello-00002-2lb`.

Приложение успешно запустилось и продолжило отображать страницу `It's running!`.

<img width="910" height="495" alt="image" src="https://github.com/user-attachments/assets/4ccd36f1-c5a0-4933-b84c-ed7d0d4f6223" />


Изменение порта не вызвало ошибки, поскольку тестовое приложение поддерживает настройку порта через переменную окружения `PORT`, передаваемую Cloud Run.

### 4. Управление трафиком между версиями

В разделе `Revision History → Manage traffic` было выполнено переключение трафика между двумя версиями.

Первоначально 100% запросов направлялись на новую версию. Затем весь трафик был переключён на первоначальную версию.

<img width="537" height="477" alt="image" src="https://github.com/user-attachments/assets/99337a7d-373e-45c2-bc00-e0e2e6e07401" />
<img width="910" height="495" alt="image" src="https://github.com/user-attachments/assets/bba54d3c-24eb-4d79-81c6-a3d4610a3fe6" />

При попытке установить распределение 50/50 возникла ошибка: максимальное количество экземпляров сервиса было ограничено одним, тогда как трафик должен распределяться между двумя версиями.

Для устранения ограничения максимальное количество экземпляров увеличено до двух.

После этого успешно настроено распределение:

| Версия | Порт | Доля трафика |
|---|---|---|
| hello-00001-vdd | 8080 | 50% |
| hello-00002-2lb | 8090 | 50% |

<img width="920" height="255" alt="image" src="https://github.com/user-attachments/assets/add3f2c0-ea52-486a-aba9-a35e906f7c15" />

При обновлении страницы были получены ответы от обеих версий приложения. При этом содержимое страницы оставалось одинаковым.

Таким образом, проверена возможность перераспределения запросов между версиями Cloud Run без изменения публичного адреса сервиса.

### 5. Удаление ресурсов

После завершения экспериментов сервис `hello` был удалён из Cloud Run вместе с его версиями.

## Вывод

В ходе лабораторной работы были изучены основные возможности Cloud Run: развёртывание контейнерного приложения, автоматическое масштабирование, просмотр логов и метрик, управление версиями и распределением трафика.

Эксперимент показал, что тестовое приложение продолжает работать после изменения порта с 8080 на 8090. Также была проверена возможность переключения трафика между версиями в пропорциях 100/0 и 50/50.

Установлено, что настройки максимального количества экземпляров могут ограничивать распределение трафика между версиями.

Получены практические навыки развёртывания и мониторинга облачных приложений без самостоятельного управления серверами.
